# 补剂配置、喂养联动与自定义睡眠设计

## 目标

在不改变现有喂养、补剂和睡眠历史记录口径的前提下：

1. 在“我的”页面维护家庭共享的补剂配置。
2. 在喂养时选择并同步记录本次服用的一个或多个补剂。
3. 让“其他记录 → 补剂”复用补剂配置并允许修改本次剂量。
4. 在睡眠页面补记一段由用户指定起止时间的完整睡眠。

## 补剂配置

新增家庭共享的 `SupplementConfig` 模型：

- `id`
- `name`：唯一、必填
- `emoji`：展示图标
- `defaultAmount`：默认剂量，字符串类型
- `defaultUnit`：默认单位
- `isActive`：是否可用于新记录
- `createdTime`
- `updatedTime`

新增补剂配置模块和 `/supplement-configs` 接口，支持查询、新增、编辑、停用和恢复。默认查询只返回启用项，管理页可请求包含停用项。删除采用软停用，历史记录不受影响。

数据库迁移初始化当前已有的“维生素D、DHA、钙”配置。配置是所有宝宝共享的家庭字典，与现有辅食字典保持一致。

“我的”页面新增“补剂管理”入口。管理页可维护名称、emoji、默认剂量和默认单位，并可停用或恢复配置。

## 补剂记录快照

现有 `Supplement` 记录继续保存服用当时的名称、剂量和单位，不增加对 `SupplementConfig` 的强关联。修改、改名或停用补剂配置不会改变历史记录。

共享类型新增 `SupplementConfigVo`，前端新增补剂配置 API。补剂 emoji 使用统一解析规则：显式配置优先，缺省时显示 `💊`。

## 喂养时添加补剂

喂养页面对全部喂养类型增加“补剂添加”开关，默认关闭，不影响现有行为。

开启后显示启用中的补剂配置，采用双列卡片展示 `emoji + 名称`，支持多选。未配置可用补剂时，引导用户前往“我的 → 补剂管理”。

保存时：

1. 先调用现有喂养记录接口创建一条喂养记录。
2. 按用户勾选的配置逐条调用现有补剂记录接口。
3. 每种补剂创建一条独立补剂记录。
4. 补剂 `takeTime` 与本次 `feedingTime` 相同。
5. 补剂名称、剂量和单位取保存瞬间的配置快照。

喂养与补剂记录在历史页中保持为各自独立的时间线项目。如果喂养成功但个别补剂失败，页面明确提示“喂养已保存，部分补剂记录失败”，不将整个操作误报为失败，也不重试或重复创建喂养记录。

## “其他记录 → 补剂”

现有手工补剂名称选项改为启用中的补剂配置单选网格。选择配置后自动带出默认剂量和默认单位；用户可只修改本次记录的剂量或单位，修改结果不回写配置。

没有启用配置时提示先前往“我的 → 补剂管理”。保存仍调用现有补剂记录接口。

## 自定义睡眠

睡眠页面保留现有“开始睡觉”和快捷睡眠功能，新增“自定义睡眠”入口。

点击后打开底部表单：

- 默认结束时间为当前时间。
- 默认开始时间为当前时间前 1 小时。
- 用户选择开始时间和结束时间。
- 不显示白天/夜间选择。

睡眠类型根据开始时间自动判断：

- `06:00–18:00` 为 `DAYTIME`。
- `18:01–次日 05:59` 为 `NIGHT`。

保存前校验结束时间晚于开始时间，且结束时间不晚于当前时间。通过后调用现有完整睡眠记录接口，后端计算 `durationMinutes`，成功后返回首页。

现有“开始睡觉”流程仍保留白天/夜间选择；自动判断只用于自定义睡眠。

## 错误处理

- 补剂配置名称去除首尾空格后不能为空或重复。
- 默认剂量和单位允许为空；从喂养创建补剂记录时原样传递可用值。
- 停用配置不出现在新记录选择器中，但管理页和历史快照仍可见。
- 自定义睡眠的无效时间区间在前端阻止提交；后端同时拒绝结束时间早于或等于开始时间，避免绕过前端写入无效记录。
- 所有提交按钮在请求期间禁用，避免重复点击创建重复记录。

## 验证

- Prisma schema 校验、客户端生成和迁移检查。
- 后端测试覆盖补剂配置的新增、重复名称、停用，以及睡眠时间区间校验和自动类型判断。
- 前端测试覆盖补剂 emoji 回退、配置默认值映射、自定义睡眠类型判断和时间校验。
- 前后端构建通过。
- 容器重新构建后检查迁移日志与 API。
- 移动端浏览器验证补剂管理、喂养多选补剂、其他记录补剂默认值、自定义睡眠保存及历史页结果。

## 范围约束

- 不修改既有历史补剂记录。
- 不改变喂养类型及辅食关联逻辑。
- 不删除现有快捷睡眠和进行中睡眠功能。
- 不新增第三方依赖。
- 不处理与本功能无关的工作区改动。
